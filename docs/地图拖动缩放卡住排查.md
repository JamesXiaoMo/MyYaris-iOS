# 地图拖动/放大偶发卡住排查

日期：2026-10-18；修复版本：0.4.3+15。只改ios_app，保留用户现有签名/Info.plist修改、Keychain、分类/收藏、3D、玻璃Tab及导航确认流程。

## 问题判断与修复

用户报告移动/放大地图有时直接卡住。本轮未获取原版挂起现场或主线程堆栈，因此不能证明唯一根因，也不能用构建通过代替间歇故障消除的真机结论。

代码中发现并处理的冲突路径：

1. 原生MKMapView之外额外添加UIPanGestureRecognizer/UIPinchGestureRecognizer，同时允许所有自定义识别器与地图手势工作。已删除这两个竞争识别器，拖动和捏合交给MapKit。单击选点改用不会阻止MapKit手势的tap观察器；不修改MapKit内部识别器/使用私有API。
2. 点选事件会触发Flutter居中及抽屉动画，导致原生地图高度变化。现在Flutter记录整个多触点序列，最后一根手指离开/取消前不接受地图点选；原生单击延迟300ms，第二次触摸、双击、相机变化都会使其失效。定位迟到结果不在手势期间抢回视野。
3. 地图触摸期间固定地图视图尺寸，即使抽屉状态同时变化也不重建平台视图。所有触点释放/取消后恢复正常布局；Tab离开/App失活时释放残留触点状态。
4. 原生地图每次渲染完成都会通知ready，Flutter此前重复setState。现在原生只在首次成功或错误恢复时通知，Flutter也忽略重复ready，减少缩放中的无效重建。

排查了Flutter本地SDK实现：RenderUiKitView按识别器Factory类型比较，同类型Set重建本身不会重置手势，因此**没有把普通重建Factory闭包直接当成已证实根因**。本轮固定Factory集合便于保持配置稳定。

### 针对性的修复

本机Flutter3.44.4的MapKit工厂注册采用默认 `FlutterPlatformViewGestureRecognizersBlockingPolicyEager`。Flutter官方仓库的[MapKit同类问题150478](https://github.com/flutter/flutter/issues/150478)描述了“Flutter按钮仍可交互，MapKit在触摸按钮后只能操作一次、后续缩放拖动失效”的相同类别现象；[平台视图触摸丢失问题191267](https://github.com/flutter/flutter/issues/191267)也报告了新iOS上默认eager阻断路径可能失效，但它主要针对WebView，**不是本机MapKit根因证明**。

当前SDK公开头文件 `FlutterPlugin.h` 仅有Eager与WaitUntilTouchesEnded，没有新报告中使用的DoNotBlockGesture。因此没有复制不存在的枚举、升级SDK或修改Flutter引擎。仅将地图工厂注册改为公开支持的 `FlutterPlatformViewGestureRecognizersBlockingPolicyWaitUntilTouchesEnded`，保留完整原生触摸序列；首页3D工厂及其他平台视图注册不变。原生阻断策略与Dart层 `EagerGestureRecognizer` 是不同层次，不能混为一谈。

[Flutter官方iOS Embedder头文件](https://api.flutter.dev/ios-embedder/_flutter_plugin_8h_source.html)及本机实际头文件明确该策略在touchesEnded之后才阻断识别。是否消除此目标机故障仍以真机重复操作为准。

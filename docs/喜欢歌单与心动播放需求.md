# 喜欢歌单与真实心动播放语义

用户要求：默认播放来源是当前网易云账号“我喜欢的音乐”；列表循环与随机均针对该歌单；心动使用真实网易云心动推荐，不以相似歌曲或普通随机冒充。默认来源不等于启动App、登录恢复就自动播放。

## 已查明的缺口

- iOS喜欢列表目前分页读取，选曲仅发送play_track单曲；现有set_loop/set_shuffle没有队列来源字段，不能确保它们操作的是喜欢歌单。
- 车机现有play_track走本地匹配或远端单流，模式操作应用当前播放器来源；不能只在手机切图标并宣称整个喜欢歌单循环/随机已实现。
- 后端现有intelligence接口失败会返回mode=simi_fallback或empty。仅mode=intelligence才可表示真实心动成功，失败不能悄然换推荐模式。

## 三端必须冻结的行为

1. 默认喜欢来源，普通循环与随机在完整喜欢列表内运行，按has_more持续分页，不能只处理前30首；不得预下载/探测整个歌单音频。
2. 车机持有实际连续播放与游标，手机后台/退出不应成为下一曲依赖。后端与车机明确队列ID/版本/来源、当前曲目、模式、去重和账号切换状态。
3. 心动从当前已验证Owner的喜欢歌单/种子获取真正推荐队列，失败显示不可用，保持已有播放状态，不回退本地样例、相似歌曲或随机。
4. 需要确定手动搜索点歌与喜欢队列的关系、模式切换是否保持当前曲目、心动补队列以及返回喜欢歌单的规则，避免手机与车机双重推进。
5. 不可播跳过须有上限、原因可见；不要持续循环重试失败歌曲，不以ack或applied代替实声验收。

已交既有产品经理协调后端/车机，iOS仅编辑ios_app；不修改共享契约，不部署。等待最小冻结接口，不把本页建议当已部署API。

独立客户端准备：FavoritePlaybackIntent仅定义用户意图，不序列化为假想队列命令；requireTrueIntelligence拒绝fallback/empty/非法推荐及超量批次，保留上游顺序并去重。尚未连接现有UI/生产请求，不能据此称心动或喜欢队列已实现。不改变现有已安装0.5.7+25，不在本轮前置检查播放/导航或修改网易云账号。

独立验证：新增3项意图/心动响应回归通过，静态分析无问题；不是完整队列或实际心动播放验收。既有已发布页面和签名配置保持，后端/车机契约与真实联调结果待产品经理反馈。

## V2.2文档交付后的独立核对

后端本阶段交付根契约7a43c7a与后端文档1bf196b，仅为Frozen Specification - Pending Implementation；不是已部署API。未据此发送set_playback_mode/switch_queue或替换当前安装版。

iOS计划使用一个明确的模式选择菜单呈现“喜欢歌单循环 / 喜欢歌单随机 / 网易云心动”，单曲循环放兼容选项；不盲轮转立即触发心动请求。已应用模式以实际车机applied_mode为准，请求模式只显示待应用；搜索点歌是临时单曲来源，显式返回喜欢歌单。

提交给产品经理的接口核对点：

- 队列GET不能因允许phone就向普通账号泄露全局Owner喜欢列表；复用既有Owner/admin边界及目标车机授权，车机仅访问自身绑定来源。
- 文档stream_url的HTTP/loopback示例不能直接供手机播放；iOS保持HTTPS，元数据解析暂剔除stream_url，后续需冻结安全解析路径。
- 后续分页需支持queue_id/version钉住同一快照或在变化时409，明确版本重启持久化与心动追加/去重语义，不能混两版歌单误报完整。
- 切模式时是否保留当前播放/暂停状态、如何原子切换单曲队列、resume在空队列时如何初始化喜欢来源，需要具体定稿；不通过手机双重推进下一曲。
- seek字段现有seek_ms与新文档position_ms需兼容/统一；状态信封及新字段须实际透传，不能只写文档。

独立客户端草案模型MusicQueuePage/MusicQueueAccumulator尚未接入UI/网络，7项本地队列/心动响应测试通过，静态分析无问题。覆盖65首跨页完整性、未确立总数不报完整、版本变化拒绝混页、分页索引/has_more矛盾，以及不转发元数据HTTP流地址。具体严格字段校验仍以最终审核契约为准，不能据此宣称车机已支持完整歌单、随机或心动。

## 2026-10-20 播放统一修订（覆盖早期测试入口说明）

- 用户显式点播放且未选来源时，默认完整、当前已验证 Owner 的 `netease_favorite`。循环顺序首尾循环；随机在全量元数据内无放回遍历。搜索显式单曲使用 `single_track`，自然结束停止；选择循环/随机明确返回喜欢歌单。
- 打开 App、登录恢复、WS 重连不发起播放，也不暂停已有播放。车机仅恢复已有快照的元数据和 cursor/position；既无快照也无来源时，等待用户点播放才准备喜欢队列。手机不后台代下一曲。
- 模式切换保留播放/暂停状态。当前歌曲仍在目标快照时保留其索引与音频源，不重新加载同曲、不归零进度；正常暂停 resume 不采用服务器迟到的旧 cursor 覆盖车机实际位置。冷播放器恢复采用服务器实际 cursor/position。
- `CarMusicQueueController` 是唯一队列调度器；just_audio 始终只加载当前一首，原生 loop/shuffle 关闭，由 completed 事件驱动下一首。首页、内置页、系统媒体按钮统一进入后端播控管线；移除本地三样例默认源及第三方 MediaSession 模式分叉。
- 心动只接受真实 `intelligence` 上游结果；`simi_fallback`、`empty`、普通随机与空数组均失败并保留旧状态。首批生成只准备快照；切模式指令 pending 后仅由车机 applied 激活。GET 未存在的心动来源返回 `QUEUE_NOT_READY`，不回喜欢伪装成功。
- 心动 `is_complete=false` 表示未来推荐尚可续批，**不等于当前有限批次元数据不可加载**。客户端仍必须分页完整加载 `total` 首并验证 `queue_state=ready`、版本、索引和前缀；`batch_index` 由服务器给出。
- 心动续批携带 `device_id`、`queue_id`、`queue_version`、稳定 `request_id`、`batch_index`、`seed_song_id` 和可选 `playlist_id`。同 ID 同参数在调用上游前重放缓存；不同参数 409。只允许上一批尾曲或实际当前曲作种子，最多总计 5 批/150 首，不生成本地版本号。失败不换来源；耗尽停止并显示原因。
- 元数据完整分页不等于媒体预下载：只按需读取当前曲媒体流，接受后端同源可信 HTTPS 或解析到该后端的相对地址，保留严格 TLS。不可播按有限尝试跳过，最多连续 3 首；失败有可见原因，错误回滚原队列。授权/心动准备失败保持旧状态。
- HTTP/WS 命令串行执行并按 command_id 去重，自动完成事件也进入相同执行序列；过期/重复/迟到 ACK 在修改实际状态之前检查，包含同 queue_id 的旧模式 ACK。`received` 不代表 applied，applied 不代表真机实声。
- 车机 `status_seq` 发出前持久化，冷进程使用持久化水位与当前时钟的最大值递增；并发状态构建串行。后端仅接受严格更大的序列，相等重复不覆盖；`updated_at` 继续发送整数毫秒，并保留服务端整数/ISO 兼容修复。
- 后端 HTTP `/music/control/command` 也接受绑定车机自身 token，执行同一管线；车机不能控制/读取别的设备，WS 不能伪装 phone/car 角色。普通用户的 Owner 资产门禁仍保留。旧 `set_loop`/`set_shuffle` 归一化到正式模式；不支持的语义显式失败。
- 三个主要菜单为喜欢循环、喜欢随机、网易云心动。兼容单曲循环仍可经协议使用，手机仅在已应用该模式时显示兼容项。手机歌曲详情的心动按钮复用统一模式入口，不再独立生成并冒充播放队列。

验证使用隔离 SQLite、fake 上游、真实 HTTP/WS 路由、fake just_audio 原生平台和本地回环 HTTP。没有发送生产播放命令、调用真实心动/点赞/导航或实车 OBD。构建、部署、设备安装和实际出声必须分别记录，不能相互代替。

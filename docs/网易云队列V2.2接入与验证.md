# 网易云队列 V2.2 接入与验证

核对日期：2026-10-19。当前客户端版本：0.5.9+27；初次接入版本：0.5.8+26。本轮后端交接实现 f9399e3、根契约 9b74a69；依据根音乐队列契约、API-V2 三端契约、后端 API 参考及实际 OpenAPI。部署文件一致性由调度独立核验，本客户端未再次 SSH。

## 初次接入（0.5.8+26）

- 明确菜单：喜欢歌单循环、喜欢歌单随机、网易云心动、兼容单曲循环。只有新鲜车机状态确认 queue_v2、账号具备 Owner/admin 与目标设备控制权限时才允许模式操作。缺能力不回退旧命令。
- 实际模式来自车机 applied_mode；requested_mode 仅表示待应用。command ack/applied 不替代车机模式或音频实声。临时搜索单曲另行标示，不伪称喜欢循环。
- 队列浏览仅 GET，不激活、不播放；读取 qid/version/source/total/is_complete/has_more，后续分页固定快照，409 清理已读分页并等待用户刷新，不混合版本。跨账号、域名及设备切换丢弃旧数据与迟到响应。
- 元数据严格检查 song_id、track_id、顺序及重复项；只接受约定相对流路径或当前后端同源 HTTPS 地址，不探测整份歌单、不预下载音频。
- HTTP/WS 状态信封统一解析，保留状态序列与实际队列字段；旧序列不覆盖新状态。seek 三别名冲突在本地拒绝。模式请求采用 seed_song_id、实际 expected_queue_id/version 等正式字段。
- Owner 队列 403 不清 MyYaris 登录、不误判为车机授权失效；401 走现有会话失效处理。心动空结果、未建立快照及上游错误不显示假成功，不走 simi 回退。
- 保留已有 Keychain、首页 3D、地图、抽屉、收藏和导航明确确认；前后台及登录恢复不新增自动播放。

## 历史阻碍记录：冷启动喜欢点歌（已由后续修正解除）

核对后端 app/api/control.py 的 play_track 分支：成员判断只检查 get_active_queue；不属于已激活队列时创建 single_track。app/services/control_service.py 的冷队列 GET 创建 activate=False 的只读快照。因此仅 GET 得到完整喜欢快照后点歌，仍可能退为单曲；向手机返回快照不等于激活它。

客户端对该情况零命令拦截，提示喜欢队列尚未由车机应用。只有实际车机已应用 favorite 队列，才按固定 qid/version 读取成员并进入一次 play_track 路径。不会用手机先切模式再点歌两命令拼接，也不将 snapshot 当 active。需后端提供/确认单次原子“按喜欢快照成员开始播放”路径后再解除冷启动限制。当前不能宣称完整喜欢点歌闭环。

## 冷启动成员点播修正（0.5.9+27）

依据调度审核通过的后端 cae0097、根契约 8800a35 更新；部署与健康核对由调度完成，本轮未再次请求生产端点。上一节的零命令拦截是 0.5.8 阶段行为，现已移除，替换为以下正式路径：

1. Owner/admin 与目标车机授权、新鲜 queue_v2 能力检查仍保留。浏览器选择使用其只读 snapshot 的 queue_id/version；从喜欢列表点歌则先 GET source=netease_favorite，再固定同一快照分页查成员。检查来源、总数、版本、索引及重复项，不将只读快照当 active。
2. 保留原有单曲可播性检查；仅检查用户选择的曲目，不探测整个歌单。验证后只提交一次 play_track：source=netease_favorite、queue_id、queue_version、song_id/track_id、匹配的 queue_index。元数据来自授权快照，不信任旧列表展示字段。
3. expected_queue_id/version 只从新鲜实际车机状态获取；冷启动无 actual 时省略，active single 转喜欢时保留 single 的 actual 前置条件。浏览 snapshot 不会被填入 expected 字段。音频探测后再次检查会话、权限、能力及已有 actual 前置条件。
4. 服务端登记 pending、ACK 后晋升 active 的语义由车机实际状态体现；本客户端不提前修改 queue_id/version/applied_mode，也不分配版本。搜索点歌继续显式 single_track。
5. 409 版本、404 非成员、422 来源/索引、403 权限有具体错误，不回退单曲、不盲重试。解析期间防重复；账号/域名/设备切换或后台导致迟到请求取消，不发送旧指令。

## 2026-10-20 播放统一修订（覆盖早期测试入口说明）

- 用户显式点播放且未选来源时，默认完整、当前已验证 Owner 的 `netease_favorite`。循环顺序首尾循环；随机在全量元数据内无放回遍历。搜索显式单曲使用 `single_track`，自然结束停止；选择循环/随机明确返回喜欢歌单。
- 打开 App、登录恢复、WS 重连不发起播放，也不暂停已有播放。车机仅恢复已有快照的元数据和 cursor/position；既无快照也无来源时，等待用户点播放才准备喜欢队列。手机不后台代下一曲。
- 模式切换保留播放/暂停状态。当前歌曲仍在目标快照时保留其索引与音频源，不重新加载同曲、不归零进度；正常暂停 resume 不采用服务器迟到的旧 cursor 覆盖车机实际位置。冷播放器恢复采用服务器实际 cursor/position。
- `CarMusicQueueController` 是唯一队列调度器；just_audio 始终只加载当前一首，原生 loop/shuffle 关闭，由 completed 事件驱动下一首。首页、内置页、系统媒体按钮统一进入后端播控管线；移除本地三样例默认源及第三方 MediaSession 模式分叉。
- 心动只接受真实 `intelligence` 上游结果；`simi_fallback`、`empty`、普通随机与空数组均失败并保留旧状态。首批生成只准备快照；切模式指令 pending 后仅由车机 applied 激活。GET 未存在的心动来源返回 `QUEUE_NOT_READY`，不回喜欢伪装成功。
- 心动 `is_complete=false` 表示未来推荐尚可续批，**不等于当前有限批次元数据不可加载**。客户端仍必须分页完整加载 `total` 首并验证 `queue_state=ready`、版本、索引和前缀；`batch_index` 由服务器给出。
- 心动续批携带 `device_id`、`queue_id`、`queue_version`、稳定 `request_id`、`batch_index`、`seed_song_id` 和可选 `playlist_id`。同 ID 同参数在调用上游前重放缓存；不同参数 409。只允许上一批尾曲或实际当前曲作种子，最多总计 5 批/150 首，不生成本地版本号。失败不换来源；耗尽停止并显示原因。
- 元数据完整分页不等于媒体预下载：只按需读取当前曲媒体流，接受后端同源可信 HTTPS 或解析到该后端的相对地址，保留严格 TLS。不可播按有限尝试跳过，最多连续 3 首；失败有可见原因，错误回滚原队列。授权/心动准备失败保持旧状态。
- HTTP/WS 命令串行执行并按 command_id 去重，自动完成事件也进入相同执行序列；过期/重复/迟到 ACK 在修改实际状态之前检查，包含同 queue_id 的旧模式 ACK。`received` 不代表 applied，applied 不代表真机实声。
- 车机 `status_seq` 发出前持久化，冷进程使用持久化水位与当前时钟的最大值递增；并发状态构建串行。后端仅接受严格更大的序列，相等重复不覆盖；`updated_at` 继续发送整数毫秒，并保留服务端整数/ISO 兼容修复。
- 后端 HTTP `/music/control/command` 也接受绑定车机自身 token，执行同一管线；车机不能控制/读取别的设备，WS 不能伪装 phone/car 角色。普通用户的 Owner 资产门禁仍保留。旧 `set_loop`/`set_shuffle` 归一化到正式模式；不支持的语义显式失败。
- 三个主要菜单为喜欢循环、喜欢随机、网易云心动。兼容单曲循环仍可经协议使用，手机仅在已应用该模式时显示兼容项。手机歌曲详情的心动按钮复用统一模式入口，不再独立生成并冒充播放队列。

验证使用隔离 SQLite、fake 上游、真实 HTTP/WS 路由、fake just_audio 原生平台和本地回环 HTTP。没有发送生产播放命令、调用真实心动/点赞/导航或实车 OBD。构建、部署、设备安装和实际出声必须分别记录，不能相互代替。
